Team Humanity / 01

Use whatever tools you want. Own the result.

Generate it. Pair on it. Search for it. Write it by hand. SlopProof does not care where the first draft came from. Before the patch enters a shared codebase, someone should understand what it changes and stand behind it.
Tools can generate code.
They cannot take responsibility.Humanity is a practice:
judgment, care, accountability.

One patch. One SHA. One accountable response.

A pull request is a promise.

Reviewers inherit the consequences of every merge. SlopProof asks the author to account for the patch while its context is still live.

01 / PIN

Bind the check.

SlopProof pins a required check to the pull request’s exact head SHA.

02 / START

Open the challenge.

The author starts a timed, patch-specific question when they are ready.

03 / RESPOND

Show the reasoning.

A response and one follow-up stay private for maintainer review.

04 / APPROVE

Release that SHA.

Approval clears this revision. Push again and the proof expires.

Product surface / interactive concept

Firm process. Calm interface.

The challenge feels like a focused workbench, not an exam room. Switch between contributor, maintainer and repository views.

How does rollback protect concurrent readers?

MOSS–47K · 9f31c2e

Readers must either see the old valid snapshot or the fully published candidate. They must never observe the half-applied state.

The patch captures the old state before publish and registers restoration for callback failure. The follow-up should explain whether restoration happens before the failure escapes.

  • Maintainer review reason
