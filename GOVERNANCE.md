# Governance

SlopProof currently uses a maintainer-led model.

[Pascal Kienast](https://github.com/pascalkienast) is the founding maintainer and
has final responsibility for releases, security decisions, repository policy
and the hosted service. Maintainers should explain material product and security
decisions in issues, pull requests or architecture documents.

Regular contributors may become maintainers after sustained work across code,
tests, review and privacy boundaries. A new maintainer needs the existing
maintainer's approval and a documented scope of access.

No contributor receives production evidence, provider payloads or deployment
secrets merely by becoming a code maintainer. Production access follows a
separate least-privilege decision.

Changes to the license, recording protocol, evidence retention ceiling,
biometric non-goals, model authority or code-execution boundary require an
explicit public proposal before implementation.
